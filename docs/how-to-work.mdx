---
title: How to work with Lumbridge TUI
description: Run Lumbridge TUI locally, inside SSH, or through remote attach.
---

Run Lumbridge TUI where the work lives. Attach from wherever you are.

Lumbridge TUI is a background session server plus one or more terminal clients. Panes keep running in the server. Clients attach, detach, and render the session.

## Local work

Start Lumbridge TUI from the project directory:

```bash
lumbridge-tui
```

Lumbridge TUI starts or attaches to your local background session automatically. You do not manage sockets. Run shells, servers, tests, and agents normally inside panes.

Detach the client with `ctrl+b q`. Your panes keep running.

Reattach later:

```bash
lumbridge-tui
```

If you want to end the session and stop its panes, stop the server:

```bash
lumbridge-tui server stop
```

## Remote work through normal SSH

SSH to the machine that has the code and credentials, then run Lumbridge TUI there:

```bash
ssh you@server
lumbridge-tui
```

This works like a terminal multiplexer. Your shell is remote. The Lumbridge TUI server is remote. The agents and panes run on the remote machine. Detach with `ctrl+b q`, disconnect, then SSH back and run `lumbridge-tui` again.

Use this path when you already live inside an SSH shell, when you are on a phone or tablet SSH client, or when you want the simplest setup.

## Work from your phone

Lumbridge TUI works on your phone without a mobile app or web dashboard. Install any SSH client, connect to the machine where your agents run, and start Lumbridge TUI there:

```bash
ssh you@server
lumbridge-tui
```

The same persistent Lumbridge TUI session opens in your phone terminal. The TUI adapts to narrow screens, so you can inspect agents, switch workspaces, and check panes without leaving SSH.

On iPhone, apps like [moshi](https://getmoshi.app/) work well.

## Remote work from your local terminal

Attach through SSH without opening a shell first:

```bash
lumbridge-tui --remote workbox
lumbridge-tui --remote ssh://you@server:2222
```

The remote server keeps the panes running and sends their terminal content and session state over SSH. Your local Lumbridge TUI draws the UI using your local theme and presentation settings.

Use this path when you want the remote session to feel local. The client runs on your machine, so local desktop features such as image clipboard paste can be bridged to the remote server. If you SSH first and run `lumbridge-tui` on the server, Lumbridge TUI runs entirely on that server and cannot read your local desktop clipboard.

For repeat targets, put the host in your SSH config:

```text
Host workbox
  HostName server.example.com
  User you
  Port 2222
```

Then attach with:

```bash
lumbridge-tui --remote workbox
```

## Which path to use

Use `lumbridge-tui` for local work. Use `ssh you@server` then `lumbridge-tui` when you want Lumbridge TUI to behave like tmux on that remote shell or when you are using a phone SSH client. Use `lumbridge-tui --remote <host>` for a local UI attached to one remote session, including local clipboard image paste. To keep Local and several SSH machines in one window, save them with `lumbridge-tui machine add <host> --label <label>`; see [Connecting machines](connecting-machines.mdx).

For remote bootstrap details, named remote sessions, custom binaries, and direct terminal attach, see [Persistence and remote access](persistence-remote.mdx).
